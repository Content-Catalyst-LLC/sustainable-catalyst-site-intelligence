# v3.26.0 Country Dropdown Interaction Audit

## Reproduced defect

The selector received focus, then lost it to `#viewTitle` roughly 250 milliseconds later. The trigger was the browser-reliability route-focus listener responding to repeated `scsi:workspace-state` events generated by background production-truth evaluation. Native select menus close when their owning control loses focus.

## Corrective contract

1. Repeated state updates on the same route may update status text but may not move focus.
2. Route-heading focus runs once per route change.
3. Active form controls retain focus during background data, map, truth, and recovery updates.
4. The native selector keeps browser-managed scrolling and keyboard navigation.
5. Wheel events over the selector are not cancelled by the application.
6. The direct application and WordPress iframe behave identically.

## Browser gate

The mandatory gate loads the complete country catalog, verifies every option is unique, confirms Kenya and Brazil are present, and checks that the selector is enabled, visible, and accepts pointer interaction. It focuses the selector, dispatches repeated workspace-state events and DOM mutations, waits for asynchronous observers, and confirms focus remains on the control. It then selects the first catalog entry, the last catalog entry, and Brazil, verifying Data Truth follows every selection. The same sequence runs in direct and iframe modes.

## Cross-platform validation repair

The original package additionally assumed that pressing Home and End on a closed native selector would change its value in every headless browser. Chrome on macOS does not guarantee that behavior because the native popup is owned by the operating system. That assertion was removed; all user-visible interaction guarantees remain tested directly.
