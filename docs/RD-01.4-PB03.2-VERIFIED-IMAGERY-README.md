## What this implements

1. **FIG-GEO01 geospatial renderer**, using the existing 26 September 2026 original Copernicus Sentinel-2 PNG on the Raspberry Pi. Independently checks its exact SHA-256, validates dimensions, interprets the documented regional bbox, georectifies the preview to EPSG:32629, and emits a source-derived GeoTIFF, high-res PNG and standalone SVG plus SHA-256 manifests and a read-only handoff.
2. **Cloud quality support**: optional genuine same-grid SCL GeoTIFF. Reports actual Sentinel-2 class-based cloud/shadow/no-data fractions; absent SCL remains *unknown*. Even with an operator-supplied matching-response declaration, the local tool cannot assert trusted receipt verification, so it never auto-approves imagery.
3. **Official boundary support, optional**: accepts SHA-verified GeoJSON polygon with sanity checks. The tool neither downloads nor invents a County Wexford polygon. Rights need source-specific approval.
4. **FIG-PB01 scientific evidence graphic** generated from a cited data register (Illinois basalt vs Minnesota slag/coarse-basalt vs southeast-Ireland returned concrete, no pooled cross-study coefficient).
5. **FIG-PB02 MRV pathway** generated from an explicit monitoring and carbon-fate process, visibly **conceptual—not observed Wexford CDR**.
6. **Output contracts** for a future **trusted Site Intelligence object** and **owner-scoped Publication Studio figure import**. This package **does not itself create a signed project, accept arbitrary file paths over HTTP, mutate original research or publish**.

## Why no automatic figure approval?

The 2026-09-26 scene was acquired through a *day-level least-cloud mosaic*. The selected STAC item is a **discovery reference, not proof that every source pixel came from that tile**. Original dimensions 1200×900 are an API-processed preview; the derived ground pixel size is **not native Sentinel-2 10 m data**. The Wexford viewport is a regional rectangle, **not a certified county polygon or ERW field**. The original PNG has no source-paired SCL cloud mask, and the prior visual review noted substantial clouds/shadows. Site Intelligence ownership, separate rights review, signed Workspace figure save/reopen, and document exports are still missing.

The new renderer produces review artifacts while keeping `publication.eligible = false` and `handoff.publicationEligible = false`. A future signed server adapter must independently verify owner and project membership, authoritative source receipts, rights, cloud quality, versioning and publication approvals.

## Reuse across the platform

- **Copernicus**: Sentinel-2 source image processing and optional original SCL. Sentinel-1 discovery already exists in the PB03.1 branch but radar needs calibrated SAR processing; do not run it through an RGB optical mapper.
- **NASA GIBS**: keep current Site Intelligence provider adapter; source-rendered WMS assets must carry its own license, date and projection metadata.
- **ESA WorldCover / CLMS / Irish EPA**: adapters should enter the existing source registry and spatial-research handoff after rights, CRS and source-version validation. WorldCover 2020 vs 2021 products use different algorithms, so naive pixel-difference maps must not be reported as land-cover change.
- **Tailte, Planet, Airbus**: deferred until a confirmed license and access controls permit use.
- **Publication Studio**: import only checksum-verified approved SVG/PNG under existing authenticated project permissions. Public Site Intelligence source processing cannot grant private Workspace ownership.
